## Overview

v1.3 ships four themes, ordered by dependency:

| # | Phase | Theme | Effort | Blocks |
|---|---|---|---|---|
| 0 | Discovery | Documentation + API surface mapping | 0.5 wk | All |
| 1 | Foundation | **Test suite (backend + frontend + e2e)** | 3 wk | All feature phases — every later phase relies on the test harness |
| 2 | Feature | **Remediation automation + alerting** | 4 wk | Phase 5 (verification of webhook security) |
| 3 | Feature | **Multi-user RBAC + audit trail** | 3 wk | Independent of 2 & 4, can run in parallel after 1 |
| 4 | Feature | **Protocol coverage (OPC UA, PROFINET, GOOSE/MMS)** | 6 wk | Independent of 2 & 3, can run in parallel after 1 |
| 5 | Verification | Full audit + release | 1 wk | — |

**Scale flag:** Four themes is **~17 wks of sequential work, ~9 wks if 2/3/4 run in parallel** (3 engineers). If you want a 4-month v1.3 with 1 engineer, drop one theme — Phase 4 (protocol coverage) is the easiest to defer to v1.4 because it's purely additive.

Each phase below is **self-contained** — drop it into a fresh chat with the bullet "Execute Phase N of `plans/v1.3-roadmap.md`" and the agent has everything it needs.

## Phase 2 — Remediation Automation + Alerting

> **Goal:** Turn findings into actionable output — exportable firewall rules per finding, remediation playbooks, and real-time alert webhooks to Slack/Teams/email.

### What to implement

1. **Remediation engine** — new module `backend/app/engine/remediation.py`
   - `class RemediationGenerator` with methods:
     - `iptables_rule(finding: Finding) -> str` — `INPUT -p tcp --dport {port} -s {src} -j DROP` etc.
     - `palo_alto_rule(finding: Finding) -> str` — PAN-OS CLI format
     - `cisco_acl(finding: Finding) -> str` — `access-list 100 deny tcp host {src} host {dst} eq {port}`
   - One method per supported vendor; each returns a single-line CLI string. Multi-line playbooks go through `playbook(finding) -> dict` (markdown + steps array)
   - Fixtures in `backend/tests/fixtures/findings/` — one JSON per protocol category

2. **Export endpoints** — extend `backend/app/api/v1/ics/findings.py`
   - `GET /api/v1/ics/findings/{id}/remediation?format=iptables|palo_alto|cisco|playbook` → returns rendered output
   - `GET /api/v1/ics/findings/export?format=...&severity=...` → bulk export, NDJSON streaming response for large sets
   - Re-use the existing `get_current_user` dependency on every new route

3. **Alerting subsystem** — new module `backend/app/engine/alerting.py`
   - Pluggable transport: `SlackTransport`, `TeamsTransport`, `EmailTransport`, `WebhookTransport` (generic POST JSON)
   - `AlertRouter` class — config-driven (`app.core.config.ALERT_RULES: list[AlertRule]`), routes by severity + category
   - Triggered from the pcap processing pipeline at `backend/app/engine/pcap_processor.py` after the findings phase
   - Rate-limit per channel (default: 5 alerts/min per transport) to prevent runaway alerts

4. **WebSocket UI notifications** — extend `backend/app/api/ws.py`
   - New channel `/ws/alerts` — broadcasts every high-severity (P1/P2) finding as it's produced
   - Frontend `frontend/src/hooks/useAlertStream.ts` — connects on app mount, dispatches to `Zustand` store
   - `frontend/src/components/AlertToast.tsx` — slide-in toast on receive, click to navigate to finding

5. **Frontend remediation UX** — extend `frontend/src/pages/AdvisoryDetail.tsx`
   - New "Remediation" tab: format selector (iptables/PA/Cisco/playbook), copy-to-clipboard, "Download all" zip
   - Re-use existing `@/services/api` — add `getRemediation(findingId, format)` and `exportFindings(filters)` methods

## Phase 3 — Multi-User RBAC + Audit Trail

> **Goal:** Roles (admin/analyst/viewer), per-user audit log on writes, team workspaces. Replaces the single-admin model.

### What to implement

1. **Role enum** — new `backend/app/models/enums.py`
   - `class UserRole(str, Enum): ADMIN = "admin", ANALYST = "analyst", VIEWER = "viewer"`
   - Migrate `User.role: Mapped[str]` → `Mapped[UserRole]` with a check constraint
   - Default for new users stays `"analyst"`

2. **First Alembic migration** — `backend/alembic/versions/001_rbac_audit.py`
   - Add `users.role` check constraint (it's already a string column — just add the constraint)
   - New table `audit_log` — columns: `id`, `user_id` (FK users), `action` (str), `resource_type` (str), `resource_id` (str), `details` (JSON), `created_at`
   - New table `workspaces` — columns: `id`, `name`, `owner_id` (FK users), `created_at`
   - New table `workspace_members` — `workspace_id`, `user_id`, `role` (override per workspace)
   - First run: `cd backend && alembic upgrade head`

3. **Permission decorator** — extend `backend/app/api/deps.py`
   - `def require_role(*roles: UserRole)` → returns a FastAPI dependency that raises `403` if `current_user.role` not in the allowed set
   - Usage: `current_user: User = Depends(require_role(UserRole.ADMIN))`
   - Apply to every write/delete endpoint in `backend/app/api/v1/admin.py`, `backend/app/api/v1/ics/findings.py` (disposition update), session deletion, user management

4. **Audit middleware** — new `backend/app/api/middleware/audit.py`
   - Captures method + path + user_id + status_code + request_id for every non-GET to `/api/v1/`
   - Skips `/auth/login` (would log credentials)
   - Async write to `audit_log` via a background task — never blocks the response
   - `GET /api/v1/admin/audit?user_id=&action=&since=` — admin-only audit query endpoint

5. **Workspace switching** — backend
   - All session/finding/device queries get an optional `workspace_id` filter
   - User's default workspace = first one they're a member of
   - JWT token gains `workspace_id` claim; switching workspace = re-issue token

6. **Frontend RBAC UX**
   - `frontend/src/hooks/useRole.ts` — read role from auth store, expose `can(action: string) -> bool`
   - Hide every "Delete", "Disposition", "Settings" button when `useRole().can('write') === false`
   - New page `frontend/src/pages/admin/UserManagement.tsx` — CRUD users + roles (admin-only)
   - New page `frontend/src/pages/admin/AuditLog.tsx` — filterable audit table

- ❌ **Do NOT** check role inside the route body — always use `Depends(require_role(...))` so it shows up in OpenAPI

## Phase 4 — Protocol Coverage Expansion

> **Goal:** Add three industrial protocol parsers covering ~70% of the gap in current ICS coverage.

### What to implement

For each protocol, follow the existing pattern in `backend/app/engine/protocol_parsers.py` exactly:
- Module-level function `parse_<protocol>(payload: bytes, src_ip: str, dst_ip: str, ts: datetime) -> list[dict]`
- Return a list of dicts each with at minimum `{type, timestamp, src, dst, summary, raw_offset, severity}`
- Register the protocol in `identify_protocol(dport, sport, payload)` at line 89
- Add the protocol to `frontend/src/pages/ProtocolAnalyzer.tsx` filter list (read it first — same UI code already lists the existing 6)

### 4a — OPC UA Binary (port 4840)

- Library: `pip install asyncua` — use only the encoder/decoder, not the client/server
- Decode the OPC UA SecureConversation message type (`MSG`), extract `RequestHeader` and the service-specific request body
- Findings to surface: write/call operations (`WriteRequest`, `CallRequest`), subscription creation by anonymous identity, AddNodes by non-admin
- Sample pcap fixture from Wireshark sample captures: https://wiki.wireshark.org/SampleCaptures#opc-ua

### 4b — PROFINET (EtherType 0x8892, also UDP 34962/34963/34964)

- No mature pure-Python lib. Parse manually using `struct` against the [PROFINET protocol spec excerpt](https://wiki.wireshark.org/PROFINET) — focus on PNIO RT frames + CM (Context Manager) for device discovery
- Findings to surface: DCP Set requests (configuration changes), CMRPC connect/release, IO data with new producer IDs
- Sample pcap: https://wiki.wireshark.org/SampleCaptures#profinet

### 4c — GOOSE + MMS (IEC 61850)

- Library: `pip install libiec61850` (Python bindings) — extracts GOOSE PDUs from raw L2 frames (EtherType 0x88B8)
- MMS runs over TCP 102 (same port as S7comm — disambiguate by ISO 8073 COTP header inspection; S7's TPKT version 3, MMS uses ASN.1 BER directly)
- Findings to surface: GOOSE message with `stNum` regression (replay attack indicator), MMS Write requests to grid control objects, unauthorized GOOSE publisher (new MAC on a known GooseID)
- Sample pcap: https://github.com/iec61850hub/test_captures

### Frontend integration

- `frontend/src/pages/ProtocolAnalyzer.tsx` — add three new entries to the protocol filter dropdown
- `frontend/src/pages/NetworkTopology.tsx` — add color tokens for OPC UA / PROFINET / GOOSE edges (re-use existing semantic palette, do NOT invent new colors)
- No new API endpoints — the parsers feed the existing pcap processing pipeline

### Documentation references (copy from)

- `backend/app/engine/protocol_parsers.py:176-245` — `parse_modbus` is the cleanest reference implementation. Copy its structure exactly
- `backend/app/engine/protocol_parsers.py:89-174` — `identify_protocol` dispatcher; extend the if-ladder
- `frontend/src/pages/ProtocolAnalyzer.tsx` — read first, copy the filter pattern for the new entries
